# 원본 YUT 기준 단계적 개선

**상태: 검증 대기 · 우선순위: 높음 · 갱신: 2026-11-12**

실행 기준은 **`Yut/Yut.xcodeproj` / scheme `Yut`**이다. 원본 외형·모으기 연출·물리 실행기를 유지하면서 게임 규칙·권한 검증·AR 생명주기를 보완했다. 실기기의 물리 체감·공유 공간 정렬·발열은 측정 전이다.

## 초기 이식 범위 — 2026-11-11

아래는 당시 이식 범위다. 이후 평면·충돌 최적화는 [현재 AR 발열 QA](../ar/ar-overheating.md)에서 별도 반영했으며, 현재 제외 상태로 읽지 않는다.

| 범위 | 반영한 동작 | 상태 |
| --- | --- | --- |
| 1. 게임 규칙·선택 | 다른 말 직접 탭으로 재선택, 선택 취소, 반복 업기 선택, 경로·빽도 이력, 그룹 이동·잡기, 낙 재던지기, 이동 불가 빽도, 완주·승자·재경기 | 자동 검증 통과, 실기기 검증 대기 |
| 2. AR·통신 연결 | 자원 준비 후 진입, 공유 공간 맵·앵커·배율, 협업 데이터 송수신, 호스트 확정 상태·차례별 권한, 오류 재시도·퇴장, 수동 던지기, 중단·복구 | 자동 검증 통과, 실제 두 기기 검증 대기 |
| 3. 안전하게 줄일 수 있는 부하 | 단독 플레이 협업 해제, AR 중복 실행 제거, 단계만 바뀔 때 말 재배치 생략, 배치 후 평면 표시 제거, 효과음 사전 준비, 중단 시 센서·카메라·타이머·작업·오디오·햅틱 정리 | 코드·회귀 확인, 발열 감소량 미측정 |
| **4. 평면·충돌 최적화** | **사용자 요청으로 제외. 평면 갱신 간격·병합 큐·충돌 형상 캐시를 도입하지 않음** | 실기기 비교 전 보류 |

기능별 반영 전 차이는 [17개 항목 목록](yut-feature-gaps.md), 터치 방식은 [입력 QA](../game/yut-board-tapping.md)에 있다.

| 연결 초기화가 게임 전 내비게이션까지 초기화 | 실제 진행 중인 게임이 종료될 때만 게임 종료 콜백을 발행한다. 방 목록의 뒤로가기 회귀를 확인했다. |

## 원본 물리 보존 근거

작업 직전 파일과 다음 구간을 대조했다. **취소·수명 관리와 통신 표시 경로는 바뀌었으므로 파일 전체가 동일하다는 뜻은 아니다.**

| 항목 | 확인 결과 |
| --- | --- |
| 실제 투사 | 매번 원본 템플릿 복제·convex 생성, 질량 5, 정적/동적 마찰 1/1, 반발 0 유지 |
| 위치·회전·속도 | 윷마다 현재 카메라를 조회하는 순서, 전방 -0.1m·간격 0.01m, 축 회전, 수평 1 + 위 3, 0.01초 뒤 속도 적용 구간 일치 |
| 정지 판정 | `YutModel` SHA-256 일치. 1초 대기·0.1초 간격·기존 단일 정지 판정 유지. |
| 사물 충돌 | 실기기 앵커 물리 설정·윷판 충돌 박스·평면 갱신마다 형상을 생성하는 경로 유지 |
| 연출·리소스 | 모으기 View와 리소스 136개 SHA-256 일치. 원본 모델·텍스처·이미지는 교체하지 않음 |

**후속 면 판정 수정:** 같은 날 원본의 좌표 판정 오류가 확인돼 면 방향 계산만 월드 기준으로 보완했다. 이식 당시의 면 판정 함수 원본 일치는 현재에 적용되지 않는다. 투사·정지 조건은 유지하며 [별도 QA](../game/yut-result-mismatch.md)에서 회귀 57개·빌드 2종과 실기기 대기를 추적한다.

시뮬레이터에는 카메라·바닥과 지원하지 않는 그림자 옵션 제외가 필요하다. 이 분기는 실기기 설정에 적용되지 않는다. 비교 근거: `/tmp/yut-hybrid-baseline.json`, `/tmp/yut-hybrid-original-YutManager.swift`, `/tmp/yut-hybrid-physics-checks.json`.

## 플레이 화면 X 버튼 제거

**상태: 검증 대기 · 2026-11-11.** 사용자 요청에 따라 PlayView 우측 상단 게임 나가기 X 버튼, 전용 확인창과 표시 상태를 제거했다. 화면 레이아웃·게임 규칙·AR·윷 물리 코드는 변경하지 않았다. 오류 안내의 방 나가기와 승리 화면의 종료 경로는 유지한다.

iOS·iOS Simulator 빌드 성공, 변경 코드의 새 Swift 컴파일 오류·경고 없음. 기존 AR UI 테스트는 제거된 버튼을 누르는 단계 대신 배치 후·투사 후 버튼 부재를 확인하도록 갱신했다. 첫 실행은 배치 후 X 부재를 확인했으나, 수동 던지기 입력 후 UI 응답 시간 초과로 실패했다. 샘플에서 `Scene.subscribe` → CoreRE 이벤트 구독 내부의 메인 스레드 반복을 관찰했다. 같은 코드 재실행에서는 배치·모으기·투사·결과 후 진행과 X 부재 확인이 모두 통과했다(UI 1개). 첫 지연의 원인은 미확정이며 해결 완료로 보지 않는다. 실기기 화면 확인은 대기다.

결과: `/tmp/yut-remove-exit-ui.xcresult`(시간 초과), `/tmp/yut-remove-exit-ui-retry.xcresult`(통과). 샘플: `/tmp/yut-remove-exit-hang.sample`. 빌드 로그: `/tmp/yut-remove-exit-device.log`, `/tmp/yut-remove-exit-simulator.log`. 규칙·물리를 바꾸지 않아 단위 테스트는 재실행하지 않았다.

## 말판 배치 안내·방장 권한 — 2026-11-12

**상태: 검증 대기.** 배치 조작은 방장만 표시한다. 방장·참가자 모두 각 기기의 인식량에 따라 **“주변 공간을 스캔해주세요”** 게이지를 표시하고, 참가자의 인식량이 기존 기준에 도달하면 **“방장이 말판을 배치 중입니다”** 안내로 전환한다.

- **확인한 구조:** ARCoordinator의 배치·확정에는 방장 권한 검사가 이미 있었다. 반면 PlacementControls는 역할 없이 로컬 AR 단계만 받았다. 공유 앵커 추가·기존 앵커 복귀 경로가 `.adjusting`을 설정하므로 참가자 화면에도 조정 안내·배치 버튼이 표시될 수 있었다. 실제 두 기기에서 이 경로를 재현한 결과는 아니다.
- **수정:** 처음에는 참가자의 배치 관련 단계를 대기 안내로 통일했다. 후속 요청에 따라 참가자도 로컬 인식량이 부족하면 스캔 게이지를 표시하도록 변경했다. 참가자에게 다음·배치하기 버튼과 탭 배치 지시는 나오지 않는다. 카메라 준비·공간 재인식·배치 완료 상태는 기존 안내를 유지한다. ViewModel의 배치 요청도 방장만 실행한다.
- **보존:** 기존 InstructionView와 플레이어 색상 쌍을 재사용했다. AR 세션 상태·공유 맵·물리·윷 판정·게임 시작 동작은 변경하지 않았다.
- **초기 검증:** 역할별 표시 단계·참가자 요청 차단 테스트 4개(당시 매개변수 16조합)를 추가했다. 단위·통합 회귀 **89개 / 15개 suite**, iOS·시뮬레이터 빌드 2종 통과. 변경 코드의 새 Swift 오류·경고는 없으며 기존 AppIntents 메타데이터 경고만 확인했다. 기존 방장 배치→게임 시작→모으기→수동 투사 UI **1개 통과**. 테스트는 SDK 27.2 / iOS 18.3.1에서 실행했으며 임시 테스트 프로젝트만 배포 대상을 낮추고 저장소 설정은 유지했다.
- **남은 확인:** 실제 두 기기에서 방장 배치 중 참가자 안내·버튼 부재, 배치 완료 후 화면 전환, 백그라운드 복귀 안내 확인.
