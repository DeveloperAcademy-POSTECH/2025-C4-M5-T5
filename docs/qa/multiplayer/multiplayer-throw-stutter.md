# 다른 플레이어 화면의 윷 움직임 끊김

**상태: 검증 대기 · 우선순위: 높음 · 갱신: 2026-11-12**

수신 자세를 즉시 적용하던 방식을 짧은 버퍼와 위치·회전 보간으로 바꿨다. 송신 기기의 원본 물리·판정은 유지한다. **자동 검증은 통과했지만, 실제 두 기기의 충돌 장면·수신 간격·프레임·통신 부하는 아직 측정하지 않았다.**

## 원인과 적용한 변경

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 자세 송신 | 100ms마다 약 10회/초 | 투사 중에만 50ms마다 약 20회/초. 실제 처리·네트워크에 따라 간격이 달라질 수 있음 |
| 시각 기준 | 순번만 전달 | 투사 시작 기준 단조 시각도 전달. 수신 첫 표본에서 시계 차이를 보정하고 호스트 중계에서도 원본 시각 유지 |
| 화면 표시 | 패킷을 받으면 즉시 위치·회전 변경 | **100ms 표시 버퍼**에서 위치·크기는 선형 보간, 회전은 최단 회전 방향의 SLERP. 관찰 중에만 CADisplayLink로 렌더 갱신(30~60Hz 선호 범위) |
| 누락·역전 | 이전 순번 차단 | 중복·이전 순번·역행하는 시각 차단. 누락 시 남은 표본 사이 보간, 새 표본이 없으면 마지막 자세 유지. 임의 궤적 예측 없음 |
| 최종 자세 | 신뢰 전송·중간 프레임 재적용 차단 | 기존 reliable 최종 전송 유지. 버퍼의 남은 구간을 표시한 뒤 최종 값과 정확히 일치. 다른 후속 최종 패킷도 차단 |
| 중단·수명 | 별도 보간 작업 없음 | 중단·새 차례·초기화에서 재생 작업/버퍼 정리. 최종 도달 또는 1초 이상 수신이 없으면 프레임 작업 중단. 재생 버퍼 최대 32개 표본 |
| 이전 메시지 호환 | 시각 필드 없음 | 시각이 없는 패킷은 수신 시각으로 처리. 기존 메시지 디코딩 회귀 통과 |

100ms는 수신 이후 보간을 위한 **추가 표시 지연**이다. 실제 종단 지연은 네트워크·중계·첫 표본 도착에 따라 달라진다. 영상 전체가 20fps로 제한되는 것이 아니며 송신 표본 수와 화면 렌더 프레임을 구분한다. 긴 패킷 공백·빠른 충돌은 실제 기기에서 추가 확인해야 한다.

## 보존 범위

- 던지는 기기만 물리를 계산하고 관찰 기기는 물리·충돌을 제거한 표시용 엔티티를 사용한다. `YutManager.swift`·`YutModel.swift`와 리소스 136개가 작업 전 SHA-256과 일치한다.
- 게임 ID·투사 revision·발신 권한 검증, 호스트 중계, 중간 unreliable/최종 reliable 전송은 유지했다.
- 최종 일치는 **송신한 최종 자세 표본** 기준이다. 기존 정지·결과 확정 시점은 변경하지 않았다.

근거: [RemoteThrowPlayback](../../../Yut/Yut/Sources/Utility/Managers/AR/RemoteThrowPlayback.swift), [송수신·재생 수명](../../../Yut/Yut/Sources/Utility/Managers/AR/ARCoordinator.swift), [시각을 포함한 메시지](../../../Yut/Yut/Sources/Models/Game/GameMessage.swift), [호스트 중계·권한](../../../Yut/Yut/Sources/Utility/Managers/Game/GameSessionController.swift), [전송 모드](../../../Yut/Yut/Sources/Utility/Managers/Multipeer/MPCManager.swift).

회전 보간은 Apple의 [simd_slerp](https://developer.apple.com/documentation/simd/simd_slerp%28_%3A_%3A_%3A%29-u2db)를 사용한다. 렌더 작업은 수신 직후 Task를 매번 생성하는 대신 메인 런 루프의 디스플레이 링크로 수행한다.

## 검증과 남은 작업

- **전체 회귀 85개 / 15개 suite 통과.** 보간 8개 테스트에서 위치·크기·회전, 수신 지터, 누락·정지 유지, 최종 도달, 중복/역전/잘못된 시각, 이전 메시지, 새 투사/초기화, 반대 부호 쿼터니언을 확인했다.
- **실제 AR 조정자 통합 회귀:** 관찰 엔티티의 물리 제거·최종 위치 적용·늦은 중간/최종 패킷 차단·중단/복귀 후 최종 유지 통과. 중간 단계를 건너뛴 새 투사 스냅샷에서도 이전 엔티티를 정리하고 늦은 이전 프레임을 차단했다. 기존 발신 권한·호스트 중계·게임 규칙 회귀도 통과했다.
- **iOS·iOS Simulator 빌드 성공**, 새 Swift 컴파일 오류·경고 없음. 라이트·다크의 로비/AR 배치→모으기→수동 투사 UI **4개 통과**. 단일 기기의 UI 통과를 실제 멀티플레이 품질 검증으로 해석하지 않는다.
- **실기기 검증 대기:** 호스트→참가자, 참가자→호스트/다른 참가자를 나눠 빠른 바닥 충돌·회전·최종 자세, 수신 간격·누락·프레임·전력과 100ms 표시 지연을 확인한다. 다음 조정은 측정 결과를 기준으로 한다.

## 원격 투사의 효과음 연결 — 2026-11-12

**상태: 수정 반영 · 실기기 검증 대기.** 사용자의 2·3번 요청을 반영했다. 실기기 QA는 이후 사용자 요청으로 중단했다.

| 항목 | 반영 내용 |
| --- | --- |
| 모으기 | 기존처럼 공유 GameState의 gathering 진입 시 각 기기에서 재생한다 |
| 충돌 시각 | 원본 YutManager가 첫 유효 바닥 충돌음을 재생한 직후 시각을 기록한다. 충격량 0.4 이상·투사당 한 번이라는 기존 기준과 효과음 파일을 유지한다 |
| 전송 | ThrowFrame에 선택 필드 collisionTimestamp를 추가하고 후속 자세 및 reliable 최종 프레임에 같은 값을 담는다. 기존 자세 전송 경로·발신 권한·게임 ID/revision 검증과 호스트 중계를 사용한다 |
| 관찰 기기 | 기존 100ms 보간 버퍼의 재생 시각이 충돌 시각에 도달하면 같은 효과음을 한 번 재생한다. 중간 프레임을 놓쳤어도 최종 프레임의 기록으로 복구한다. 수신한 최종 자세만 바로 표시한 경우 소리도 그 표시 시점에 맞춘다 |
| 중복·중단 | 동일 투사 중복·역전 프레임·늦은 이전 투사는 기존 검증으로 차단한다. 같은 투사의 반복 효과음을 막고, 중단 중 받은 충돌음을 복귀 시 뒤늦게 재생하지 않는다 |
| 호환·부하 | 이전 메시지에는 새 필드가 없어도 디코딩한다. 충돌 시각이 없으면 임의 소리를 추정하지 않는다. 추가 전송 채널·오디오 스트리밍·상시 타이머는 만들지 않았다 |

관찰 기기는 여전히 물리·충돌을 제거한 표시용 윷을 사용한다. 원본 질량·마찰·반발·투사·판정 시점, 음원과 모으기 재생 속도는 유지했다. SoundService에는 작은 GameSoundPlaying 경계를 적용해 실제 오디오 장치 없이 재생 호출을 검증한다.

**검증:** 수정 전 관찰 기기의 충돌음 재생 횟수가 0인 통합 테스트 실패를 확인했다. 수정 후 전체 회귀 101개 / 16개 suite와 로비·방 참여·AR UI 3개가 통과했다. 별도로 중단 중 수신 시나리오를 추가한 효과음 통합 테스트 2개도 통과했다(기존 1개 재검증 포함). iOS 서명 빌드·iOS Simulator 빌드가 통과했으며 변경 코드의 새 Swift 오류·경고는 없다. 기존 AppIntents 메타데이터 경고만 남아 있다. 실기기에서 실제 청취·시각 동기화를 완료했다고 판단하지 않는다.

근거: [첫 충돌 시각 기록](../../../Yut/Yut/Sources/Utility/Managers/AR/YutManager.swift), [전송·원격 재생](../../../Yut/Yut/Sources/Utility/Managers/AR/ARCoordinator.swift), [재생 시각·일회 소비](../../../Yut/Yut/Sources/Utility/Managers/AR/RemoteThrowPlayback.swift), [메시지](../../../Yut/Yut/Sources/Models/Game/GameMessage.swift), [효과음 통합 회귀](../../../Yut/YutTests/Utility/AR/RemoteThrowSoundTests.swift).

## 작업 이력

- **2026-11-12 / 분석:** 100ms 자세 송신·보간 없는 즉시 적용·호스트 중계 구조를 확인했다. 패킷 손실·중계 기여도는 미측정이었다.
- **2026-11-12 / 수정:** 시각 필드·100ms 버퍼·프레임별 보간·투사 중 20회/초 송신·중단 정리·최종 고정을 적용했다. 빌드·회귀 통과, 실제 두 기기 비교 대기.
- **2026-11-12 / 효과음 분석:** 모으기만 공유 상태로 재생되고 첫 바닥 충돌음은 로컬 충돌에서만 재생됨을 확인했다. 원격 충돌 이벤트·재생 연결은 미구현이며 앱 코드 수정·빌드·실기기 청취 검증은 하지 않았다.
- **2026-11-12 / 효과음 연결:** 첫 충돌 시각을 자세/최종 프레임에 유지하고 같은 버퍼 시각에서 원격 효과음을 한 번 재생하도록 연결했다. 원본 물리·음원 보존, 전체 회귀 101개·UI 3개 통과. 추가 중단 통합 2개 통과, 실기기 QA는 사용자 요청으로 중단.
