# YUT 문서 안내

**현재 개발 대상: `Yut/Yut.xcodeproj` · scheme `Yut` / 갱신: 2026-11-13**

작업 상태는 [QA 현황](qa/README.md), 코드 작성 기준은 아래 문서에서 확인한다.

## 개발 기준

| 문서 | 확인할 내용 |
| --- | --- |
| [아키텍처](guides/architecture.md) | MVVM 책임, 의존성 주입, 화면·ViewModel·SubViews 구조 |
| [Swift 컨벤션](guides/swift-conventions.md) | 이름, 코드 형식, 동시성, SwiftUI 작성 규칙 |
| [디자인 시스템](guides/design-system.md) | 공용 컴포넌트, 색상·글자색 조합과 사용 기준 |
| [게임 진행·규칙](guides/game-rules.md) | AR 준비, 조작 권한, 추가 던지기·결과 선택·말 상태·승리와 중단 처리 |

개발 기준과 게임 진행 가이드는 `guides`에 모으며, AGENTS.md는 아키텍처·Swift 기준 경로를 참조한다. 변경 경과와 검증은 기준 문서가 아닌 해당 QA에 남긴다.

## QA·작업 추적

[QA 현황](qa/README.md)은 항목별 상태·최근 작업·다음 작업을 요약한다. 분석 근거와 테스트 결과는 영역별 상세 문서에서 확인한다.

```text
docs/
├── README.md                  문서 진입점
├── guides/
│   ├── architecture.md        아키텍처 기준
│   ├── swift-conventions.md   코딩 기준
│   ├── design-system.md       공용 UI 기준
│   └── game-rules.md          AR 게임 진행·규칙
└── qa/
    ├── README.md              현재 상태·최근 작업·다음 작업
    ├── ar/                    공간 인식·렌더링·발열
    ├── game/                  던지기·판정·말 조작
    ├── multiplayer/           원격 재생·연결 종료
    ├── ui/                    색상·목록·설정
    ├── structure/             화면 대응·디렉토리 정리
    └── migration/             초기 이식 범위·기능 비교 근거
```

## 작성·갱신 규칙

- **기준·기능·QA·과거 기록**의 역할을 나눈다. 새 문서를 만들기 전에 같은 주제의 기존 문서를 확인한다.
- QA 상세는 **문제 → 확인한 사실·가설 → 수정 → 검증 → 남은 작업** 순서로 작성한다. 상단에는 상태·우선순위·갱신일을 둔다.
- 현황판의 한 행에는 최근 변경과 다음 작업을 각각 한 문장으로 쓴다. 전체 테스트 로그·긴 분석을 복사하지 않는다.
- 이력은 상세 문서에 날짜별로 짧게 남긴다. 현황판의 최근 작업은 3개까지 유지하고, 이전 작업은 해당 상세 문서에서 확인할 수 있게 한다.
- 코드 확인·원인 가설·자동 검증·실기기 실측을 구분한다. 실기기 확인이 남으면 `검증 대기`이며, 문서 이동만으로 완료 상태를 바꾸지 않는다.
- 경로를 옮길 때는 문서·소스 링크와 제목 앵커도 갱신한다. 삭제된 파일의 링크는 현재 참조 가능한 자료로 갱신하거나 제거한다.
